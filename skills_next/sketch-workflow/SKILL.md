此技能是 `Sketch` 代码生成自动化体系的"总指挥"

## 核心铁律

### 铁律 1：基于现状，能复用不重复

- **智能增量**：只生成缺失的骨架和代码，已存在的资源能利用就利用
- 通过 md 描述文档、组件文件的存在性和内容判断当前进度
- 已完成步骤**直接跳过**，绝不重复执行

### 铁律 2：你是编排者，不是编码者

- **绝对禁止**自行编写组件代码
- 你只负责调度子技能，由子技能完成具体工作
- 如发现子技能遗漏或错误，应让子技能重新执行，而非自己动手修复

### 铁律 3：进度可视化

- 每完成一个操作必须向用户展示当前进度和下一步计划
- 汇报格式：`[画板名称] 阶段X/X — 完成内容 → 下一步：调用 skill:xxx`

### 铁律 4：调度顺序严格

- 各阶段的调度顺序不可逆、不可跳跃
- `sketch-init` → `sketch-split` → `sketch-layout` → `sketch-draw`
- 如果某画板的某阶段已标记完成，直接跳过（依据 md 描述文档中的 `phase` 字段判断）

#### 调度协议

| 子技能                 | 何时调用               | 负责什么                                                 |
| ---------------------- | ---------------------- | -------------------------------------------------------- |
| `skill: sketch-init`   | 阶段 1：工作流启动时   | 枚举 zip/folder 中所有画板，用户单选                     |
| `skill: sketch-split`  | 阶段 2：画板选定后     | 分析画板结构，输出组件规划表，创建空白组件 + md 描述文档 |
| `skill: sketch-layout` | 阶段 3：组件规划完成后 | 配置路由，父组件编写子组件容器 div + import              |
| `skill: sketch-draw`   | 阶段 4：布局完成后     | 调用 analyze 提取图层数据，逐个生成组件内部代码          |

## 执行清单

以下阶段**按序号严格顺序执行**。每阶段在进入时**先检查**画板的 md 描述文档和组件文件，已完成的步骤直接跳过。

---

### 阶段 1：按需初始化

**输入**：Sketch 文件路径 `file_path`（zip 或目录）

1. [ ] **执行**：调用 `skill: sketch-init`，传入 `file_path`，由技能内部完成枚举和用户选择
2. [ ] **解析输出**：从 `skill: sketch-init` 返回结果中提取选中画板列表 `selected_artboard`
3. [ ] **记录上下文**：记录当前工作目录、file_path、selected_artboard 到工作流上下文

**汇报**：`已选择画板【selected_artboard】，准备处理`

---

### 阶段 2：按需拆解组件

1. [ ] **检查是否已规划**：查看画板入口组件的 md 描述文档是否存在
   - 存在且 `phase` 字段 >= `split` → **跳过**，输出 `[画板] 已规划，跳过拆解`
   - 不存在或 `phase` 不完整 → 继续步骤 2
2. [ ] **执行**：调用 `skill: sketch-split`
   - 传入参数：`file_path`、`page_name`、`artboard_name`
   - 如果已有空白组件但缺少完整规划表，告知技能基于现有文件增量处理
3. [ ] **验证输出**：确认 sketch-split 返回了完整的 `组件规划表`，且所有空白组件已创建
4. [ ] **记录规划表**：将当前画板的组件规划表记入上下文
5. [ ] **汇报**：`[画板名称] 阶段 2/4 — 组件规划完成，共 N 个组件` → 进入**阶段 3**

---

### 阶段 3：按需布局组件

1. [ ] **检查是否已布局**：读取画板入口组件的 md 描述文档
   - `phase` 字段 >= `layout` → **跳过**，输出 `[画板] 已布局，跳过`
   - 否则 → 继续步骤 2
2. [ ] **执行**：调用 `skill: sketch-layout`
   - 传入参数：画板信息（page_name、artboard_name）
   - 技能会根据组件规划表完成路由配置和父组件布局
3. [ ] **验证输出**：确认路由已配置、父组件已包含子容器 div 和 import
4. [ ] **更新 phase**：将画板入口组件的 md 中 `phase` 字段更新为 `layout`
5. [ ] **汇报**：`[画板名称] 阶段 3/4 — 布局完成，路由已配置` → 进入**阶段 4**

---

### 阶段 4：按需绘制组件

1. [ ] **读取组件规划表**：获取当前画板的所有组件列表（按**深度优先遍历**排序）
2. [ ] **逐个绘制组件**（按深度优先顺序）：
       a. [ ] **检查是否需要绘制**：读取组件文件 - 已有丰富实现内容且 md 中 `phase` >= `draw` → **跳过** - 空白或仅有骨架 → 继续
       b. [ ] **执行**：调用 `skill: sketch-draw` - 传入参数：组件对应的 md 描述文档路径（或组件名称）- 技能会自动读取 md 中的元数据（rect、exclude_rects、children 等）
       c. [ ] **验证输出**：确认组件代码已生成，md 中 `phase` 已更新为 `draw`
       d. [ ] **汇报进度**：`[画板名称] 阶段 4/4 — 组件 [N/M]：[ComponentName] 绘制完成`
3. [ ] 所有组件绘制完成后，将入口组件 md 中 `phase` 更新为 `complete`

**汇报**：`画板 [画板名称] 全部完成！共生成 M 个组件`

---

```
  画板处理完成！
  画板：[画板名称]
  生成组件数：M
  文件位置：<工作目录>
═══════════════════════════════════════════
```

## 组件描述文档 phase 字段说明

每个画板入口组件的 md 描述文档包含 `phase` 字段，标记当前处理进度：

| phase 值   | 含义               | 阶段             |
| ---------- | ------------------ | ---------------- |
| `init`     | 画板已选定，未拆解 | 阶段 1           |
| `split`    | 组件规划已完成     | 阶段 2           |
| `layout`   | 路由和布局已完成   | 阶段 3           |
| `draw`     | 至少一个组件已绘制 | 阶段 4（进行中） |
| `complete` | 该画板全部完成     | 完成             |

分析子技能（sketch-split）在创建 md 描述文档时，`phase` 初始值设为 `split`。
布局子技能（sketch-layout）完成后，将 `phase` 更新为 `layout`。
绘制子技能（sketch-draw）完成后，每个组件在各自的 md 中将 `phase` 更新为 `draw`。
工作流在画板全部绘制完成后，将入口组件 md 的 `phase` 更新为 `complete`。
