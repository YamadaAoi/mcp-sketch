此技能会根据用户输入或上下文推断当前需要处理的画板，找到画板对应入口页面组件的`md`描述文档，根据文档中的`组件规划表`，完成页面的路由配置和相关组件的布局

# 阶段隔离声明

- 本技能只负责编写组件的**排版样式**，不负责组件的功能实现
- **禁止**在本阶段编写任何逻辑、事件处理代码
- **本阶段只处理有子组件的父组件**，无子组件的叶组件由 `sketch-draw` 单独处理

## 核心铁律

### 铁律 1：基于现状，复用代码 (关键)

- 路由复用：在更新路由配置前，**必须**读取现有路由文件。如果路由已存在，**直接跳过**
- 文件复用：在更新组件前，**必须**检查组件内容。如果组件已实现布局样式，**直接跳过**

### 铁律 2：适配项目技术栈

- **禁止臆测项目技术栈**
- 生成文件前，读取 `package.json` 的 `dependencies` 确定技术栈，查看已有组件文件确定写法
- 路由配置、导入方式、样式写法都必须与项目现有代码一致

### 铁律 3：组件的位置和大小完全由父组件控制

- 每个组件的大小都是`width: 100%; height: 100%;`，位置都是`position: relative;`
- **必须**由父组件根据`组件规划表`中的布局信息，为子组件编写合适的容器，控制子组件的位置和大小

## 执行步骤

### 步骤 1：读取画板描述文档

- 从用户输入或上下文推断当前需要处理的画板，找到对应入口页面组件的`md`描述文档
- 读取描述文档，获取`组件规划表`

### 步骤 2：路由配置更新

- 读取现状：根据项目技术栈找到项目中的路由配置文件
- 遍历规划的路由，检查是否已配置当前画板对应入口页面组件：
  - **已配置**：直接跳过
  - **未配置**：按项目规范插入新路由，与现有路由写法保持一致（lazy-load / eager import / 其他模式）

### 步骤 3：组件布局更新

- 从画板所属入口页面组件开始，按照组件依赖树，从上到下**深度优先遍历**`组件规划表`中的每个组件
  - 根据`组件规划表`中的信息，查看当前遍历的组件是否有`直接子组件`：
    - **无**：直接跳过
    - **有**：
      - 根据表中布局信息，为`直接子组件`编写合适的`div`容器，通过css样式控制子组件的位置和大小
        - 子组件的`div`容器名**禁止**与子组件的名称一致，且必须是唯一的
        - **必须**使用`响应式`布局，灵活运用`%`，`flex`，`calc`等css布局技术
      - 正确`import`子组件到当前组件，并填入相应的`div`容器中

### 步骤 4：更新 phase 状态

- 将入口页面组件的描述文档中的 `phase` 字段更新为 `layout`
- 如有其他组件的 md 文档中的 `phase` 字段，也一并更新为 `layout`

### 步骤 5：代码质量自检 (强制)

根据项目实际配置运行检查，确保代码无语法错误且风格一致。先通过 `package.json` 的 `scripts` 和配置文件判断可用工具。

```shell
# 如果项目配置了 prettier（有 .prettierrc* 或 prettier 脚本）
npx prettier --write <组件文件路径>

# 如果项目配置了 eslint（有 eslint.config.* 或 lint 脚本）
npx eslint <组件文件路径> --fix --no-ignore
```

- 若 eslint 报错（未修复的），**必须逐条修正**代码后重新运行，直到无报错
- 若项目有 `typecheck` 脚本（`tsc --noEmit` 等），运行 `npx tsc --noEmit` 检查组件文件类型错误。报错则修正后重试，直到通过
- 若项目没有对应的检查工具，跳过即可

## 后续动作

- **工作流模式**下组件布局完成后，由 `skill: sketch-workflow` 调用 `skill: sketch-draw` 进行组件绘制
