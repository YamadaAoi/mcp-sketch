# Sketch Draw Check Skill

批量审核绘制的组件是否符合要求（代码质量 + 视觉比对）

## 核心约束

- **绝不自行编写代码**：只审核和报告，不修改文件
- **禁止执行任何写入操作**
- **状态文件只读**：禁止直接新建、修改或删除 `.sketch-cache/` 下的状态文件。状态仅通过 `RECORD_STATE` 输出标记，由 Leader 负责写入

## 执行步骤

参数由调用方传入：

- `page_name` — 页面名
- `artboard_name` — 画板名
- `file_path` — 设计稿文件路径

`design_file_name = basename(file_path, '.zip')`

### 步骤 1：读取状态文件

读取 `.sketch-cache/artboards/{design_file_name}/{page_name}/{artboard_name}/progress.json`

- 若不存在，返回失败信息：`画板{page_name}-{artboard_name}中间状态不存在`

### 步骤 2：提取待检查组件

从状态文件的 `components` 数组中，筛选 `status = 'draw-done'` 的组件

- 若没有 `draw-done` 状态的组件，返回：`没有需要检查的组件`

### 阶段一：基础代码检查（批量）

对每个 `draw-done` 组件执行以下检查：

#### 3a. UI 组件库使用检查

- 输入框、按钮、选择器、开关等基础组件，是否使用了项目 UI 组件库中的组件

#### 3b. 未使用的 import

- 检查组件文件中是否有导入了但未使用的 import 语句

#### 3c. 代码质量检查

读取 `.sketch-cache/proj-init.md` 获取格式化、代码检查、类型检查的完整命令并执行：

- 若项目没有对应的检查工具，跳过即可
- 执行时精确到 `component_path` 组件文件（如 `eslint <component_path>`），无需全量扫描
- typecheck（如 `tsc --noEmit`）不支持指定文件，需全量检查，过滤与 `component_path` 相关的错误
- 若有报错，检查报错内容是否涉及 `component_path` 组件文件：
  - 涉及 → 记录失败，附上与 `component_path` 相关的具体错误和修复命令
  - 不涉及（报错全是已有项目错误）→ 无视，视为通过

#### 3d. 汇总基础检查结果

将所有组件的检查结果汇总

- **存在失败组件** → 立即返回结果，不执行阶段二
- **全部通过** → 继续执行阶段二

### 阶段二：视觉比对（仅基础检查全部通过时执行）

#### 4a. 读取预览信息

- 从状态文件获取 `previewPath`（设计稿预览图路径）和 `previewUrl`（浏览器预览 URL）

#### 4b. Playwright MCP 截图

检查当前是否拥有 Playwright MCP 提供的浏览器工具（如 `browser_navigate`、`browser_screenshot`）：

- **可用** → 按顺序执行：
  1. 使用 `browser_navigate` 打开 `{previewUrl}`，观察页面渲染内容
  2. 若目标组件在首屏不可见（需点击 tab、滚动翻页等），使用 `browser_click`、`browser_hover` 等工具逐步交互直到组件可见
  3. 使用 `browser_screenshot` 截取全页截图，保存到 `.sketch-cache/artboards/{design_file_name}/{page_name}/{artboard_name}/` 目录下
  4. 记录截图路径 `screenshotPath`
  5. 继续执行 4c-4g 进行视觉比对

- **不可用** → 跳过视觉比对，输出警告：

```
⚠️ 未检测到 @playwright/mcp，无法自动截图进行视觉比对。请在你的 AI 平台中配置 @playwright/mcp MCP 服务以获得截图比对能力
```

#### 4c. 读取截图和设计稿预览图

- 读取截图文件 `screenshotPath`
- 读取设计稿预览图 `previewPath`

#### 4d. 逐项视觉比对

从以下维度逐一比对截图与设计稿预览图，列出所有差异：

**布局结构**：页面整体布局是否与设计稿一致（header/body/footer 等大区块的上下顺序和比例），是否有元素明显缺失或多余

**组件位置与大小**：各组件的左右/上下位置是否与设计稿对齐，各组件的宽度/高度比例是否合理

**间距**：组件之间的间距是否明显过宽或过窄，内边距是否明显异常

**色彩**：背景色、文字色、边框色等主色调是否明显偏离设计稿

**文字**：是否有文字截断、重叠或明显溢出容器

#### 4e. 问题分级

| 级别      | 说明                               | 处理方式                   |
| --------- | ---------------------------------- | -------------------------- |
| P0 - 严重 | 布局错乱、关键元素缺失、功能不可用 | 必须修复后才能进入下一阶段 |
| P1 - 中等 | 间距/大小偏差、颜色偏差            | 建议修复，可酌情放行       |
| P2 - 轻微 | 像素级偏移（< 5px）、装饰性差异    | 可忽略                     |

#### 4f. 排除设计差异

以下差异属于设计与实现之间的**正常偏差**，不属于 bug，不计入问题列表：

- 设计稿中的文本占位符与实际渲染的真实文本内容不同
- 字体渲染差异（系统字体 vs 设计稿字体）
- 设计稿中未实现的交互态（hover/focus）
- 设计稿中的固定文案与实际项目的动态数据

#### 4g. 考虑屏幕尺寸差异

浏览器窗口尺寸通常不等于设计稿尺寸，因此截图与设计稿预览图必然存在整体缩放差异。比对时注意区分**可接受偏差**和**真实 bug**：

**可接受偏差（放行）：**

- 整体页面内容等比缩放导致的元素间距、大小整体变化
- 由于浏览器宽度小于设计稿宽度，部分内容自然折行/换行
- 页面居中对齐时，两侧空白区域大小不同
- 出现滚动条导致页面可用宽度略微减小
- 所有元素保持相对位置关系不变，仅整体缩放或偏移

**真实 bug（需报告）：**

- 局部元素脱离整体缩放规律，相对于其他元素出现位置偏移（如按钮未跟随父容器右对齐）
- 本该对齐的元素明显错位（两列顶部对齐偏差 > 10px）
- 内容明显溢出容器（文字被截断、覆盖、超出边界）
- 元素缺失或重叠
- 本应在视口内的关键内容被截断不可见

**判断原则**：如果能用"浏览器窗口比设计稿窄/宽了 X 像素"统一解释所有偏差，则为可接受偏差；如果某个元素的行为无法用整体尺寸变化解释（如单独错位、不对齐、溢出），则为真实 bug。

## 输出格式

### 阶段一失败（基础检查不通过）：

```
基础组件审核结果（共 {total} 个，{passCount} 个通过，{failCount} 个失败）：

通过：
- {component_path_1}
- {component_path_2}

失败：
- 组件路径：{component_path}
  错误类型：<UI组件库未使用 | 未使用import | 代码质量问题>
  错误描述：<具体错误信息>
  修复建议：<修复方案描述>
（逐个列出所有失败组件）
DRAW_CHECK_FAILED
RECORD_STATE: 仅记录通过的组件为 draw-check-done，失败组件保持 draw-done
```

### 阶段二通过（含视觉比对）：

```
基础检查通过，视觉比对完成：
设计稿：{previewPath}
截图：{screenshotPath}
视觉差异：{P0数量}个严重, {P1数量}个中等, {P2数量}个轻微
{P0/P1 问题逐条列出，含问题描述和修复建议}
DRAW_CHECK_SUCCESS
RECORD_STATE: components[{componentPath}].status = draw-check-done（所有通过的组件）
```

### 阶段二通过（跳过视觉比对）：

```
基础检查通过，视觉比对已跳过（@playwright/mcp 未配置）
DRAW_CHECK_SUCCESS
RECORD_STATE: components[{componentPath}].status = draw-check-done（所有通过的组件）
```

### 阶段二存在 P0 问题：

```
基础检查通过，视觉比对完成，存在需修复的问题：
设计稿：{previewPath}
截图：{screenshotPath}
视觉差异：{P0数量}个严重, {P1数量}个中等, {P2数量}个轻微
{P0/P1 问题逐条列出，含问题描述和修复建议}
P0_FOUND
DRAW_CHECK_FAILED
```

### 阶段二失败（截图/读取失败）：

```
截图比对失败：
- 错误类型：{截图失败 | 文件读取失败}
- 错误描述：{具体错误信息}
DRAW_CHECK_FAILED
```
