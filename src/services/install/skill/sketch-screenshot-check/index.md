# Sketch Screenshot Check Skill

截图比对设计稿预览图和浏览器实际渲染效果，找出视觉差异

## 核心约束

- **绝不自行编写代码**：只比对和报告，不修改文件
- **禁止执行任何写入操作**

## 执行步骤

参数由调用方传入：

- `page_name` — 页面名
- `artboard_name` — 画板名

### 步骤 1：读取项目配置

读取 `.sketch-cache/proj-init.md`，获取启动命令（如 `npm run dev`、`pnpm dev` 等），服务已停止需重启时使用。

### 步骤 2：读取状态文件

读取 `.sketch-cache/artboards/{page_name}-{artboard_name}.json`

- 若文件不存在，跳过之后所有步骤，返回失败信息：`画板{page_name}-{artboard_name}中间状态不存在`
- 若文件存在，从中获取：
  - `filePath` — Sketch 文件路径
  - `previewPath` — 设计稿预览图路径
  - `previewUrl` — 浏览器预览 URL
  - `width` — 画板宽度
  - `height` — 画板高度

### 步骤 3：调用 screenshot 截图

```bash
npx -y mcp-sketch screenshot -f "{filePath}" --pn "{page_name}" --an "{artboard_name}" -u "{previewUrl}" -c "{启动命令}"
```

**参数说明**：

| 参数   | 必填 | 说明                                                                                                       |
| ------ | ---- | ---------------------------------------------------------------------------------------------------------- |
| `-f`   | ✅   | Sketch 文件路径，从状态文件的 `filePath` 获取                                                              |
| `--pn` | ✅   | 页面名                                                                                                     |
| `--an` | ✅   | 画板名                                                                                                     |
| `-u`   | ✅   | 截图 URL，从状态文件的 `previewUrl` 获取                                                                   |
| `-c`   | ❌   | 启动命令，从 `proj-init.md` 获取，服务已停止需要重启时才传                                                 |
| `-p`   | ❌   | 项目根目录。如果当前工作目录就是项目根目录（能直接运行启动命令），则无需传；否则需要传入 `-p` 指定项目路径 |

记录返回的截图保存路径 `screenshotPath`

### 步骤 4：读取截图和设计稿预览图

- 读取截图文件 `screenshotPath`
- 读取设计稿预览图 `previewPath`

### 步骤 5：逐项视觉比对

从以下维度逐一比对截图与设计稿预览图，列出所有差异：

**5a. 布局结构**

- 页面整体布局是否与设计稿一致（header/body/footer 等大区块的上下顺序和比例）
- 是否有元素明显缺失或多余

**5b. 组件位置与大小**

- 各组件的左右/上下位置是否与设计稿对齐
- 各组件的宽度/高度比例是否合理

**5c. 间距**

- 组件之间的间距是否明显过宽或过窄
- 内边距是否明显异常

**5d. 色彩**

- 背景色、文字色、边框色等主色调是否明显偏离设计稿

**5e. 文字**

- 是否有文字截断、重叠或明显溢出容器

### 步骤 6：问题分类

对发现的差异进行分级：

| 级别      | 说明                               | 处理方式                   |
| --------- | ---------------------------------- | -------------------------- |
| P0 - 严重 | 布局错乱、关键元素缺失、功能不可用 | 必须修复后才能进入下一阶段 |
| P1 - 中等 | 间距/大小偏差、颜色偏差            | 建议修复，可酌情放行       |
| P2 - 轻微 | 像素级偏移（< 5px）、装饰性差异    | 可忽略                     |

### 步骤 7：排除设计差异

以下差异属于设计与实现之间的**正常偏差**，不属于 bug，不计入问题列表：

- 设计稿中的文本占位符与实际渲染的真实文本内容不同
- 字体渲染差异（系统字体 vs 设计稿字体）
- 设计稿中未实现的交互态（hover/focus）
- 设计稿中的固定文案与实际项目的动态数据

### 步骤 8：考虑屏幕尺寸差异

浏览器窗口尺寸通常不等于设计稿尺寸，因此截图与设计稿预览图必然存在整体缩放差异。比对时注意区分**可接受偏差**和**真实 bug**：

**可接受偏差（放行）：**

- 整体页面内容等比缩放导致的元素间距、大小整体变化
- 由于浏览器宽度小于设计稿宽度，部分内容自然折行/换行
- 页面居中对齐时，两侧空白区域大小不同
- 出现滚动条导致页面可用宽度略微减小
- 所有元素保持相对位置关系不变，仅整体缩放或偏移

**真实 bug（需报告）：**

- 局部元素脱离整体缩放规律，相对于其他元素出现位置偏移（如按钮未跟随父容器右对齐）
- 本该对齐的元素明显错位（两列顶部对齐偏差 > 10px）
- 内容明显溢出容器（文字被截断、覆盖、超出边界）
- 元素缺失或重叠
- 本应在视口内的关键内容被截断不可见

**判断原则**：如果能用"浏览器窗口比设计稿窄/宽了 X 像素"统一解释所有偏差，则为可接受偏差；如果某个元素的行为无法用整体尺寸变化解释（如单独错位、不对齐、溢出），则为真实 bug。

## 输出格式

成功（无 P0 问题）：

```
截图比对完成：
设计稿：{previewPath}
截图：{screenshotPath}
视觉差异：{P0数量}个严重, {P1数量}个中等, {P2数量}个轻微
{P0/P1 问题逐条列出，含问题描述和修复建议}
SCREENSHOT_CHECK_SUCCESS
```

成功（有 P0 问题）：

```
截图比对完成，存在需修复的问题：
设计稿：{previewPath}
截图：{screenshotPath}
视觉差异：{P0数量}个严重, {P1数量}个中等, {P2数量}个轻微
{P0/P1 问题逐条列出，含问题描述和修复建议}
P0_FOUND
```

失败：

```
截图比对失败：
- 错误类型：{截图失败 | 文件读取失败}
- 错误描述：{具体错误信息}
SCREENSHOT_CHECK_FAILED
```
