# Sketch Code Skill

通用的开发技能，处理其他 skill 未覆盖的开发任务，包括**修改存量组件**、**提取公共组件**、**调整业务逻辑**等

## 核心约束

- **不涉及设计稿分析**：没有设计稿，不需要调用 `mcp-sketch analyze`
- **基于现有代码做精确修改**：不随意重构无关代码
- **全面理解项目规范**：必须先读 `proj-init.md`，遵守项目的代码风格和目录结构

## 执行步骤

以下步骤中的 `component_path`、`requirements`（可选）均由调用方传入上下文。

### 步骤 1：读取项目配置

- 读取 `.sketch-cache/proj-init.md` 确认技术栈、代码风格、项目结构
- 读取 `.sketch-cache/components-init.md` 了解可复用的组件
- 若 `proj-init.md` 不存在，跳过之后所有步骤，返回失败信息：`proj-init.md 文件不存在`

### 步骤 2：理解需求

分析 `requirements` 中的内容，判断任务类型：

- **修改组件**：理解要把组件改成什么样，需要改动哪些部分
- **提取公共组件**：理解要抽取哪些共性逻辑，目标组件结构如何设计
- **删除组件**：删除组件文件及对应的 `.md` 描述文件，清理项目中所有对该组件的导入引用
- **其他任务**：理解具体需求
- **修复**：`requirements` 描述的是 check 失败原因或用户反馈的修复意见

没有 `requirements` 时返回失败：`缺少 requirements，请描述需要做什么`

### 步骤 3：读取目标文件

根据需求读取对应文件：

- 修改/删除：读取 `component_path` 指向的文件

### 步骤 4：执行修改

根据需求执行精确修改：

- **与项目现有代码风格一致**：命名规范、导入方式、CSS 方案等遵循 `proj-init.md`
- **读取现有文件全部内容**，在保留现有代码的基础上做精确修改
- **不删除或重构无关代码**
- 可能需要：
  - 创建新文件（提取公共组件）
  - 修改现有文件（改组件逻辑或样式）
  - 删除组件文件及对应的 `.md` 描述文件，并清理项目中的导入引用
  - 更新导入路径和引用
  - 创建组件描述文档 `.md` 文件

**提取公共组件时要更新所有调用方**：搜索项目中所有 import 原组件的文件，提及原组件的文件，例如各 progress.json。逐文件更新导入路径为新组件路径，确保提取后项目可正常编译

### 步骤 5：更新公共组件清单

若任务类型为**提取公共组件**，在创建新组件后同步更新 `.sketch-cache/components-init.md`：

- 读取现有的 `components-init.md`
- 在「项目公共组件」表格末尾追加新组件行：`| {组件名} | {组件路径} | {一句话功能描述} |`
- 若文件不存在，跳过此步骤（Leader 后续执行 init-components 时会全量生成）

## 输出格式

成功：

```
组件【componentPath】处理完成
CODE_SUCCESS
```

失败：

```
<错误描述>
CODE_FAILED
```
